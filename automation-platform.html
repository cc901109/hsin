CASE STUDY 02 · PLATFORM / DEVOPS

Automation
Platform

隨著自動化測試服務與工具逐步增加， 平台需要處理的不只是單一工具部署， 而是 Container、CI/CD、測試服務與不同功能模組之間的整合。 我參與 Container-based Automation Platform 的建置與維運， 並負責平台部署、工具導入、Automation、Jenkins 管理 與相關架構整合工作。

ROLE Platform / Integration / Administration
STACK Kubernetes / KubeSphere / Jenkins
FOCUS Automation Platform Integration
01 / CONTEXT

當測試工具增加， 問題開始從 Tool 變成 Platform。

自動化測試環境包含不同用途的服務與工具， 各自負責特定測試功能。 當這些元件逐步 Containerize 並整合至共同平台後， 工程問題不再只是「某個服務能不能啟動」， 而是如何讓多個元件能夠穩定部署、協同運作， 並納入一致的 Automation 與維運流程。

因此平台需要同時考量 Container Runtime、 Kubernetes Workload、CI/CD、服務設定、 元件相依關係，以及後續維運方式。

ENGINEERING QUESTION

如何建立一個能承載多種 Automation Services， 並讓部署、CI/CD、設定與服務整合具備一致性的 Container-based Platform？

02 / RESPONSIBILITY

我的工作不只是在平台上部署服務。

在平台相關工作中，我主要負責 Container Platform 的部署， 並參與工具選型、架構規劃、自動化與服務整合。 同時擔任 Jenkins Service Administration， 因此需要理解從平台基礎環境到 CI/CD 以及各測試服務之間的整體關係。

01

Platform Deployment

建置與維護 Kubernetes / KubeSphere Container Platform，作為測試服務的執行基礎。

02

Tool & Service Integration

依照測試需求評估工具與服務的部署方式， 並處理不同元件之間的整合。

03

Jenkins Administration

負責 Jenkins Service Administration， 支援 CI/CD 與 Automation Workflow 的運作。

04

Architecture & Automation

從需求與元件相依關係出發， 規劃部署、Automation 與整合方式。

03 / ARCHITECTURE

把不同工具放進同一個平台， 不代表它們已經完成整合。

平台的角色是提供共同的執行與管理基礎， Jenkins 負責 Automation Workflow 與 CI/CD， 各測試服務則依照自身功能在 Container Environment 中執行。 真正需要處理的是這些層之間的介面、設定與相依關係。

04 / PROCESS

先理解服務怎麼互動， 再決定怎麼部署。

面對新的 Tool 或 Service 時， 我會先確認它在整體測試流程中的角色、 需要的資源、外部相依與其他服務的互動方式， 再評估 Containerization 與 Platform Integration 的方案。

05 / COLLABORATION

Platform Integration 本身就是跨元件協作。

團隊成員分別負責不同的測試工具與功能模組。 在整合過程中，我會與相關成員確認工具的核心用途、 使用需求、服務之間的依賴，以及資料與設定如何交換。

當多個服務需要共同運作時， 也需要討論架構、整合順序與介面， 避免單一元件雖然能獨立執行， 但無法順利進入完整的 Automation Workflow。

06 / VALIDATION

驗證的是完整 Workflow， 而不是單一 Container。

Platform Integration 完成後， 驗證範圍會從單一 Service 是否正常啟動， 延伸到服務相依、Pipeline 執行、 Automation Workflow 與實際測試流程是否能正確串接。

✓

Containerized Service 可在 Platform 正常部署與執行

✓

服務設定與必要相依關係可正確整合

✓

Jenkins / CI/CD 可與相關 Automation Flow 串接

✓

不同測試服務能進入完整的平台工作流程

07 / TAKEAWAY

Platform Engineering 的重點， 是讓元件能夠一起運作。

這段經驗讓我從單一工具的部署， 進一步理解 Container Platform、 CI/CD、Automation 與各種 Testing Services 之間的系統關係。

對我而言，平台建置並不是把多個工具集中放在 Kubernetes 上， 而是需要理解每個元件的角色與限制， 並透過架構、部署方式、Automation 與介面設計， 讓它們形成可持續運作的整體系統。
