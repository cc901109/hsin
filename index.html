ENGINEERING APPROACH

Engineering is more than making a tool run.

在實際工程工作中，我逐漸將重點從「工具如何使用」延伸到「系統為什麼這樣運作」。當 Container、Network、Host、Physical Device 與 Automation Platform 同時存在時，問題往往來自不同系統層之間的互動。

因此面對陌生需求時，我通常先釐清系統邊界與限制，再進行技術調研與方案比較，透過 PoC 驗證可行性，最後完成實作、整合與驗證。

需求釐清→架構分析→技術調研→PoC→實作整合→驗證
CASE 01

SYSTEMS / NETWORKING

Kubernetes × Physical DUT Network

當單機 Docker 測試流程遷移至 Kubernetes，Test Pod 除了需要保留 Kubernetes Pod Network，也必須連接實體 DUT 測試網路，並從 DUT-side DHCP 取得測試所需位址。

ROLEArchitecture / PoC / Integration
STACKKubernetes / Multus / macvlan
FOCUSMulti-Network Integration
PROBLEM

預設 Pod Network 無法直接取代實體測試網路。

原有 Container 可透過 Host 測試網路與 DUT 連線；進入 Kubernetes 後，需要同時維持 Cluster 通訊與實體產品測試流量。

ENGINEERING QUESTION

如何在保留 Kubernetes 預設網路的同時，為 Test Pod 增加另一個可直接進入 Physical DUT Network 的介面？

ARCHITECTURE

以 Multus CNI 建立 Secondary Network。

WORKLOADTest Pod

Default Interface + Secondary Interface

↓
MULTI-NETWORKMultus CNI → NetworkAttachmentDefinition

Attach and define secondary network

↓
NETWORKmacvlan + DHCP

Secondary interface and DUT-side IP assignment

↓
PHYSICAL NETWORKDUT Network

Product-side test environment

Pod→Multus→NAD→macvlan→DHCP→DUT
VALIDATION

驗證完整資料路徑，而非單一元件。

✓

保留 Kubernetes Default Network

✓

成功建立 Secondary Network Interface

✓

透過 DUT-side DHCP 取得測試網段 IP

✓

Container 可透過獨立測試網路與 Physical DUT 連線

CASE 03

PERFORMANCE / NETWORKING

10GbE Performance Validation

面對高速網路測試時，效能瓶頸不一定存在於單一元件。我從 Traffic Generator 到 Container 執行環境逐層檢視資料路徑，建立可重複驗證的分析方式。

ROLEValidation / Analysis / Integration
STACKTRex / DPDK / Linux / NIC
FOCUS10GbE Data Path
DATA PATH

效能問題需要沿著整條資料路徑分析。

TRex→DPDK→Linux / Driver→NIC→Network→Container / DUT

驗證時不只確認工具是否產生流量，而是檢視各層設定與執行環境是否可能影響封包處理與最終測試結果。

METHOD

建立基準，再逐層縮小變因。

01

Baseline

先建立可比較的測試條件與基準行為。

02

Layer Isolation

依序檢視 Traffic Generator、DPDK、Kernel、NIC 與 Container。

03

Environment

確認 Host、Container 與 Network Configuration 的差異。

04

Repeatability

以一致條件重複驗證，避免將單次現象直接視為結論。

TAKEAWAY

Performance 是跨層問題。

這類工作讓我更重視系統層級的資料路徑與變因控制。當結果不符合預期時，重點不是快速歸因，而是透過可重複測試逐步確認瓶頸可能出現在哪一層。

PUBLIC PORTFOLIO NOTE

未公開企業產品、內部拓樸、實際測試數據或專有設定；頁面只描述分析方法與使用的公開技術。
